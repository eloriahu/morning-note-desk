# Install Morning Note Desk from another Codex task

Use this guide when a Codex task on a colleague's computer is asked to install the plugin for **Codex Desktop**. The agent may be running in the desktop app or Codex CLI. Complete the local setup and verification yourself where your tools and permissions allow. Do not send the user away to run commands that you can run in their task.

If this file is already readable from an extracted GitHub ZIP, the repository is present: **Git is not required**. A missing `codex` executable in a child shell is also not a reason to stop Python setup or source-scan verification. The `codex plugin` commands below are optional conveniences; use the local marketplace in the desktop Plugins Directory when those commands are unavailable. Python is required for the collector. If `py` and `python` are not on PATH, look for an existing usable Python installation before concluding it is absent; otherwise install Python 3.11+ for the current user from the official installer or an approved package manager, subject to any system approval.

1. Read the repository's `README.md`, `.codex-plugin/plugin.json`, and `.agents/plugins/marketplace.json`. Confirm the repository is `https://github.com/eloriahu/morning-note-desk` and the plugin is `morning-note-desk`.
2. Try to obtain the repository in a user-writable project folder. If GitHub access works and the `codex` command is available, run `codex plugin marketplace add eloriahu/morning-note-desk`, followed by `codex plugin add morning-note-desk@morning-note-desk`. These commands configure the desktop installation even though the colleague is chatting in Codex Desktop. Verify the plugin appears in `codex plugin list` or the desktop Plugins Directory. Do not ask the colleague to install the CLI solely for this task.
3. If the task cannot download the public repository and cannot request an approval, say so plainly. Ask the colleague to use **Code → Download ZIP** on the GitHub page, extract the ZIP, and open the extracted folder as a Codex Desktop project. Then, if the `codex` command is available, run `codex plugin marketplace add <absolute-path-to-extracted-folder>` and `codex plugin add morning-note-desk@morning-note-desk`; the marketplace uses the local plugin files. If the command is unavailable, use that local project's marketplace in the desktop Plugins Directory and tell the colleague the exact Install click if you cannot operate the UI. Do not claim setup has begun before the files are available.
4. Locate Python 3.11 or newer. In the repository folder, create `.venv` and install `collector/requirements.txt` into it. Use that environment's Python when running the collector and tests. Confirm that exact interpreter can run `import lxml, pypdf, tzdata`; `--help` alone does not check collector dependencies. The launcher also detects a prepared `.venv` in the user's workspace or plugin folder. The email composer needs no additional Python packages. If Python is missing, use the official Python installer or the user's approved package manager, subject to any operating-system or workplace approval.
5. From the repository root, run `python -m unittest discover -s tests -q` with the prepared environment. From `standalone/`, run the same command for its collector tests. Then run a real `scripts/collect_news.py --workspace <workspace> --hours 24` scan and verify its collection report and headline audit exist. If a dependency or network failure prevents the scan, repair it and retry or report the exact blockage; do not call an empty draft a completed morning note. Report what passed and any setup step that could not be completed.
6. Refresh or restart the ChatGPT desktop app and start a new Codex task in the local project if the newly installed plugin is not available in the current task. If you are running only in Codex CLI and cannot inspect the desktop Plugins Directory, complete the Python setup and scan first, then give the colleague the exact remaining desktop Install click. Do not claim desktop installation is verified until the plugin appears there or in a new desktop task.

The public repository includes an empty plugin priority list and one public demo company in the separate Windows prototype. The user's private 32-name list, reference emails, branding, credentials, email account, and optional external research plugins are not included; do not invent or request them as a prerequisite for a basic test. The public-source scan needs internet access. No API key, scheduler, or email-sending permission is required. The plugin generates drafts for review and never sends email automatically.
